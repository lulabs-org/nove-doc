# nove 项目完整概述文档

## 一、项目概述

nove 致力于构建一个**面向个人、组织与企业的智能数据仓库**，作为 AI 时代的组织数据底座与 Agent 数据基础设施。

系统通过 **实时/定时多源数据汇聚 + AI 实时预处理 + 多协议对外接口 + 严格的人机权限控制**，让组织散落在各处的数据（会议、订单、用户、聊天、邮件、合同……）汇聚成**庞大而有机结合的数据资产**，供 AI、Agent 与人类按需使用。

项目的第一个落地客户为 **陆向谦实验室**（教育场景）。在完成实验室级验证后，平台将逐步拓展至：

- 专业教育机构
- 高等院校
- 企业培训与组织学习
- 泛教育与知识服务型组织
- 更广泛的个人 / 中小企业数据管理场景

最终目标是构建一个可横向复制、纵向深化的 **新一代智能数据基础设施**。

---

## 二、项目愿景与核心理念

### 项目愿景

> **让每个组织的数据，都能被 AI 理解、关联与复用。**

nove 不只是一个数据存储工具，而是一个**让数据持续增值的智能数据仓库** —— 数据进来时是孤立的记录，经过 nove 后成为有机联系的知识资产。

### 核心理念

- **数据汇聚**：把散落在会议、订单、聊天、邮件、合同等系统中的数据实时/定时汇聚到一个仓库
- **AI 关联**：AI 自动找出数据间的关联与联系，形成组织级别的"有机结合的数据仓库"
- **Agent 优先**：数据的主要消费者是 AI 与 Agent，人类通过 nove-admin 查看与操作
- **权限为本**：对 AI 的访问实行严格、全面、可审计的权限控制

---

## 三、系统定位

**企业级 · 多源 · 智能数据仓库与 Agent 数据基础设施**

nove 的系统定位是：

- **个人 / 组织 / 企业数据仓库**：统一承载多源业务数据
- **面向 AI 与 Agent**：通过 API、MCP、Skill、CLI 等接口对外提供数据交互
- **人类入口为 nove-admin**：查看与操作走管理后台
- **可配置、可扩展、可复用**：内置数据仓库格式，支持自定义方式接入新数据形态

## 四、核心特点

### 1. 多源数据汇聚

- 实时、定时从方方面面获取数据：会议数据、订单数据、用户数据、聊天记录、客户对接、用户画像、群聊数据、产品数据、邮件、合同等
- 数据接入能力持续扩展（插件或自定义接入形式）

### 2. AI 实时预处理

- 数据入库后由 AI 实时预处理（如自动对用户的参会记录进行总结）
- 自动找出数据间的关联与联系，形成组织庞大的有机结合数据仓库

### 3. 多协议对外接口

- API、MCP、Skill、CLI 等一系列接口对外提供数据交互
- 作为其他 Agent Harness 的强大数据后盾

### 4. 严格的人机权限控制

- 对 AI 实行严格、全面的权限访问控制
- AI 以独立身份接入，最小授权、全量审计

### 5. 可拓展的数据格式

- 内置数据仓库格式
- 支持通过自定义方式（插件或其他形式）接入新的数据形式

---

## 五、AI 能力归属（架构决策）

nove 的 AI 能力采用**轻/重分层**，实体归属 **nove-ai（FastAPI + Python）**：

| 任务类型 | 示例 | 归属 |
|---|---|---|
| 轻量同步 | 实体抽取、字段映射、短文本分类、单场会议摘要 | nove-api 内嵌封装（AiClient） |
| 重量异步 | Embedding 入库、语义关联发现、知识图谱构建、批量转写总结、用户画像 | nove-ai（Python），Job 化 |

- nove-api 永不直接依赖具体模型，只通过 AiClient（超时/重试/熔断/降级）调用 nove-ai
- 服务间用 HMAC 签名鉴权（详见架构文档）
- 慢任务一律异步 Job（queued → running → succeeded / failed），结果回写数据库

## 六、技术实现方向（概览）

- 前端：nove-admin（Web，人类入口）
- 后端：nove-api（NestJS，数据获取 / 存储 / 权限 / API 暴露）
- AI 层：nove-ai（FastAPI + Python，预处理 / 关联 / 图谱 / 画像）
- 数据层：PostgreSQL + Redis（+ 向量库）
- 接口层：REST API / GraphQL / MCP / Skill / CLI
- 架构原则：**可扩展、可演进、可持续、权限为本**

## 八、需求与范围

### 8.1 核心用户

- **AI / Agent**：通过 API / MCP / Skill / CLI 读取数据、执行任务（主要消费者）。
- **数据提供方**：会议、订单、聊天、邮件、合同等外部系统，向仓库推送/被拉取数据。
- **人类用户（管理员 / 业务人员）**：通过 nove-admin 查看数据、配置权限、管理数据源、审计 AI 行为。
- **开发者 / 集成方**：接入新数据源（插件/自定义格式）、构建基于仓库的 Agent 应用。

### 8.2 典型场景

- **多源数据汇聚**：会议记录、订单、用户、聊天记录、客户对接、群聊、产品、邮件、合同等实时/定时入库。
- **AI 预处理与关联**：自动总结参会记录、抽取实体、建立"用户 ↔ 会议 ↔ 订单 ↔ 邮件"等关联，形成语义层。
- **Agent 数据调用**：外部 Agent 通过 MCP / Skill / API 按权限读取仓库数据，完成总结、分析、报告等任务。
- **人类管理操作**：管理员通过 nove-admin 查看数据全景、管理数据源与权限、审计 AI 访问。
- **自定义接入**：新数据形态通过插件或自定义格式接入，扩展仓库能力。

### 8.3 范围边界（v1.0）

- 包含：核心数据源接入（会议、订单、用户）、基础 AI 预处理、API / MCP / Skill / CLI 接口、人机统一权限与审计、nove-admin 查看与操作、运营看板雏形。
- 暂不包含：移动端/桌面端、复杂低代码平台、跨组织数据联邦（可于 v1.x 规划）。

## 九、目标与建设原则

### 9.1 项目目标

- 建设组织级数据仓库：多源数据实时/定时汇聚、统一存储、权限隔离。
- AI 实时预处理：自动总结、字段映射、实体抽取；自动发现数据间的关联与联系，形成有机结合的数据仓库。
- 多协议开放：通过 API、MCP、Skill、CLI 等接口对外提供数据交互，服务 AI、Agent 与第三方系统。
- 严格的人机权限：AI 以独立身份接入，最小授权、全量审计，AI 只能在授权范围内访问数据。
- 可拓展数据格式：内置数据仓库格式，支持以自定义方式（插件或其他形式）接入新数据形态。
- 交付最小可用应用（nove-admin，Web），作为人类查看与操作入口。

### 9.2 建设原则

- 以人为本：AI 增强而非替代，人类保留最终判断权。
- 价值优先：围绕真实使用场景交付最小可用版本（MVP）。
- 渐进迭代：小步快跑、连续集成，数据与能力持续进化。
- 可替换性：模块化边界清晰，技术栈可演进、实现可替换。
- 权限为本：数据访问（尤其是 AI 访问）始终受控、可审计。
- 扁平协作：信息直达、减少流程摩擦，强调交付与反馈闭环。

## 十、成功指标（KPI）

### 技术性能指标
- **数据接入可靠性**：核心数据源（会议 / 订单 / 用户）接入成功率 ≥ 99%
- **系统响应性能**：API 平均首响 < 300ms，99% 分位数 < 1s
- **系统可用性** ≥ 99.5%，故障恢复时间 < 5min
- **接口吞吐**：峰值 QPS > 500

### 业务效果指标
- **数据汇聚覆盖**：核心数据源 100% 接入，自动沉淀率 ≥ 90%
- **AI 预处理覆盖率**：入库数据自动预处理（总结 / 抽取）覆盖率 ≥ 80%
- **权限违规** = 0，敏感信息泄露 = 0，审计记录完整率 = 100%
- **Agent 调用**：≥ 3 个外部 Agent 通过 API / MCP / Skill 稳定调用

### 用户体验指标
- **管理员满意度** ≥ 4.2/5（内测问卷）
- **数据时效**：实时数据源入库延迟 < 5min，定时数据源按计划完成
- **自定义接入**：新增一类数据源接入耗时 ≤ 1 周（插件化后 ≤ 2 小时）

### 运营效率指标
- **数据质量**：重复数据率 ≤ 5%，数据完整性 ≥ 95%
- **成本控制**：AI 模型调用成本/月 ≤ 预算目标，资源利用率 ≥ 75%

## 十二、风险与应对

- 数据源接入复杂度高 → 契约优先、统一连接器、插件化、沙箱数据先通
- LLM 效果波动 → 离线评测集、结构化输出、可追溯引用、降级兜底
- AI 访问权限风险 → 人机统一权限、最小 scope、全量审计、数据脱敏
- 资源节奏与并行冲突 → 分支并行、场景优先级、双周可交付
- 技术选型演进 → 模块边界清晰、接口稳定、可替换实现
- 数据敏感与合规 → 最小权限、脱敏、审计闭环、分级授权

## 十五、术语

- 数据仓库（Data Warehouse）：统一汇聚、存储组织多源数据的系统。
- 人机统一权限：人类用户与 AI Agent 均作为独立访问主体的权限体系。
- MCP：Model Context Protocol，模型上下文协议，供 LLM / Agent 调用数据与工具。
- Skill：面向 Agent 的技能化接口封装（如 nove-skills）。
- RAG：Retrieval-Augmented Generation，检索增强生成。
- HMAC：Hash-based Message Authentication Code，服务间请求签名鉴权。
