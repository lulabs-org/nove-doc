### 通用连接器设计
通用连接器应支持多种数据源类型，通过接口抽象实现统一接入。每个具体数据源（如飞书文档、Notion）实现各自的适配器。

### 同步策略与变更检测
增量同步机制应基于时间戳、版本号或事件通知实现变更检测，避免全量拉取带来的性能开销。

```mermaid
sequenceDiagram
participant Scheduler as 同步调度器
participant Connector as 数据源连接器
participant Detector as 变更检测器
participant Processor as 数据处理器
participant Storage as 数据存储
Scheduler->>Connector : 触发同步任务
Connector->>Detector : 查询变更记录
Detector-->>Connector : 返回变更列表
Connector->>Connector : 拉取变更数据
Connector->>Processor : 提取元数据
Processor->>Processor : 映射访问权限
Processor->>Storage : 写入统一存储
alt 存在冲突
Processor->>Processor : 执行冲突解决策略
end
Storage-->>Scheduler : 返回同步结果
```

### 数据统一处理流程
结构化与非结构化数据应通过统一管道处理，提取标准化元数据并映射原始权限模型。

```mermaid
flowchart TD
Start([开始同步]) --> Auth["认证数据源"]
Auth --> Fetch["拉取原始数据"]
Fetch --> Struct{"数据类型?"}
Struct --> |结构化| Extract1["提取字段元数据"]
Struct --> |非结构化| Extract2["提取文档属性<br/>内容摘要"]
Extract1 --> MapPerm["映射访问权限"]
Extract2 --> MapPerm
MapPerm --> CheckUpdate["检测更新冲突"]
CheckUpdate --> |有冲突| Resolve["执行冲突解决策略"]
CheckUpdate --> |无冲突| Update["更新本地副本"]
Resolve --> Update
Update --> End([同步完成])
```
