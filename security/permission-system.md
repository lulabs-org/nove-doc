# 人机统一权限体系

> 权限是 nove 数据仓库的核心设计：**人类用户与 AI / Agent 均为独立访问主体**，AI 只能在被授权范围内访问数据，且每次访问可审计。

## 一、双主体模型

nove 将访问主体划分为两类，统一纳入权限管理：

| 主体 | 接入方式 | 授权模型 | 典型行为 |
|---|---|---|---|
| 人类用户 | nove-admin（Web） | RBAC（角色 → 权限点）+ ABAC（条件） | 查看数据、管理数据源、配置权限、审计 |
| AI / Agent | API / MCP / Skill / CLI（独立身份） | API Key + scope 白名单 | 读取授权数据、执行分析任务 |

> 原则：**AI 绝不复用人类账号**。每个 Agent 拥有独立身份与独立授权，权限变更互不影响。

## 二、权限模型

### 2.1 RBAC（角色基础访问控制）

- 角色 → 权限点（permission code）
- 菜单 / 页面 / 按钮 / 操作均绑定权限点

### 2.2 ABAC（属性基础访问控制）

对资源做条件化控制，例如：
- 只能查看本组织（Tenant）的数据
- 只能读取被授权的数据源 / 数据范围
- AI scope 可精确到"数据源 × 字段 × 操作"

### 2.3 AI scope 白名单

AI / Agent 的每次访问受 scope 约束：

- 数据源范围：如"仅会议数据""仅订单数据"
- 操作范围：只读（默认）/ 受限写（需显式授权）
- 字段级：敏感字段（手机号、身份证号等）默认脱敏

## 三、身份认证

- **人类**：OAuth 2.0、JWT（短期）、会话管理
- **AI / Agent**：API Key（含 `sk_` 前缀的长期密钥）+ scope 绑定；`sk_` 格式请求需携带 User-Agent 头
- 多租户（Tenant）级数据隔离

## 四、全链路审计

- **记录**：谁（人类 / AI 身份）、何时、访问了什么数据、执行了什么操作
- **可回放**：支持行为回放与合规检查
- **TraceId 透传**：请求跨 nove-api 与智能计算服务（前期外部 Agent / 远期 nove-ai）全链路可追踪
- **告警**：越权尝试、异常访问模式触发告警

## 五、数据脱敏

- 自动识别敏感信息（手机号、身份证号、邮箱等）并模糊化处理
- 脱敏策略可按角色 / AI scope 差异化配置
- 敏感数据加密存储（Secret Manager 托管密钥）
