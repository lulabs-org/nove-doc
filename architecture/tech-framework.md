# NOVE 项目技术框架方案

> [!NOTE] 历史方案（v1.0 教育中台时期）
> 本文档写于项目定位为"实验室 AI 智脑与教育中台"时期（v1.0）。当前定位已调整为**个人 / 组织 / 企业数据仓库与 Agent 数据基础设施**（v2.0），本文档保留作为技术选型的历史参考。最新架构请见 [技术方案总览](./overview) 与 [技术白皮书](./whitepaper)。

## 推荐架构方案（基于实验室 AI 智脑与教育中台需求）

### 1. 前端技术栈 (Frontend)

#### 核心框架
- **主框架**: Next.js
  - ✅ 支持 SSR，提升知识检索页面 SEO
  - ✅ API 路由简化前后端通信
  - ✅ TypeScript 全栈一致性
  - ✅ 支持会话界面与实时交互

#### UI 设计系统
- **CSS 框架**: Tailwind CSS
- **组件库**: shadcn/ui
- **特殊组件**: 
  - 会议纪要展示组件
  - RAG 问答界面（多轮对话、引用溯源）
  - 行动项看板（类 Kanban 设计）
  - 智能体配置界面（低代码编排）

#### 状态管理与实时交互
- **状态管理**: Zustand（轻量级、适合中型应用）
- **实时通信**: 
  - WebSocket（师生互动、会议状态同步）
  - Server-Sent Events（流式 AI 响应）
- **缓存策略**: React Query（智能缓存、后台更新）

### 2. 后端技术栈 (Backend)

#### 核心框架选择
- **推荐方案**: NestJS
  - ✅ 模块化架构，适合复杂业务逻辑
  - ✅ TypeScript 原生支持，类型安全
  - ✅ 依赖注入，便于单元测试
  - ✅ 内置权限守卫（RBAC/ABAC 实现）
  - ✅ Swagger 自动文档生成

#### AI 能力集成
- **多模型协同策略**:
  - **GPT-4**: 复杂推理、报告生成、会议摘要
  - **Claude**: 长文本处理、文档分析
  - **DeepSeek**: 成本敏感场景的本地化选择
- **RAG 系统架构**:
  - Embedding 模型（text-embedding-ada-002）
  - 向量检索 + 权限过滤
  - 会话记忆与上下文管理
  - 可控更新机制（版本管理）

#### 数据存储
- **主数据库**: PostgreSQL + Prisma ORM
  - 用户权限、会议记录、行动项管理
  - 复杂关系查询（用户-部门-权限）
  - 事务一致性保证
- **向量数据库**: Pinecone → Weaviate（演进路径）
  - Pinecone: 快速启动，托管服务
  - Weaviate: 混合搜索（关键词+向量），开源可控
- **缓存层**: Redis
  - 会话状态、频繁查询结果缓存
  - 异步任务队列（BullMQ）

#### 核心服务模块
- **飞书集成服务**: OAuth 2.0 + Webhook + API 调用
- **知识库管理服务**: 文档清洗、向量化、索引构建
- **RAG 引擎服务**: 检索、推理、响应生成
- **智能体编排服务**: 低代码配置、动态路由
- **权限与审计服务**: RBAC/ABAC、操作日志、数据脱敏

### 3. 核心智脑与 RAG 系统

#### 检索增强生成（RAG）架构
- **查询理解**: LLM 意图识别与关键词提取
- **语义检索**: 
  - 向量相似度匹配
  - 权限感知过滤（用户角色 + 数据权限）
  - 混合检索（向量 + 关键词 + 时间范围）
- **上下文构建**: 
  - 检索结果排序与去重
  - 会话历史融合
  - 引用溯源标记
- **响应生成**: 
  - 多模型协同决策
  - 流式输出支持
  - 质量检测（幻觉识别、不确定性提示）

#### 知识库构建与管理
- **数据源接入**:
  - 飞书会议（转写、摘要、行动项）
  - 课程文档（PPT、PDF、Markdown）
  - 案例手册与项目文档
- **智能处理**:
  - 文档分块与摘要提取
  - 实体识别与关系抽取
  - 自动标签分类
- **版本控制**: 
  - 增量更新策略
  - 数据血缘追踪
  - 索引重建优化

#### 智能体编排引擎
- **模板化配置**: 部门智能体模板（教学、管理、咨询）
- **数据源绑定**: 可视化选择数据范围
- **能力组合**: 勾选功能模块（问答、报告、提醒）
- **动态路由**: 根据用户请求类型分发处理

### 4. 飞书集成与会议处理系统

#### 飞书 API 集成
- **OAuth 2.0 认证**: 获取企业授权与用户身份
- **Webhook 订阅**: 
  - 会议开始/结束事件监听
  - 文档更新通知
  - 日程变更同步
- **API 调用**: 
  - 会议录音/转写文本获取
  - 参会人员信息查询
  - 日程数据同步

#### 会议数据处理链路
- **语音转写（ASR）**: 第三方服务或自建模型
- **智能摘要生成**: 
  - 会议主题识别
  - 关键决策点提取
  - 讨论要点归纳
- **行动项抽取**: 
  - 任务识别与责任人分配
  - 截止时间提取
  - 优先级评估
- **结构化存储**: PostgreSQL + 向量化索引

#### 异步任务处理
- **消息队列**: Redis + BullMQ
- **任务类型**: 
  - 会议转写与摘要生成
  - 知识库索引重建
  - 定期数据同步
- **错误处理**: 重试机制 + 死信队列

### 5. 权限与安全系统

#### 权限控制模型
- **RBAC（基于角色）**: 
  - 系统管理员、部门管理员、普通用户
  - 角色继承与权限组合
- **ABAC（基于属性）**: 
  - 部门数据隔离
  - 项目级别访问控制
  - 时间窗口限制
- **数据权限**: 
  - 行级权限（用户只能看到所属部门数据）
  - 列级权限（敏感字段脱敏）
  - 操作权限（读/写/删除）

#### 安全与合规
- **数据脱敏**: 自动识别 PII（手机号、身份证）
- **审计日志**: 全链路操作记录与溯源
- **数据加密**: 
  - 传输加密（TLS 1.3）
  - 存储加密（数据库/文件）
  - 密钥管理（HashiCorp Vault）
- **访问控制**: 
  - API 限流（防 DDoS）
  - IP 白名单
  - 多因子认证（可选）

## 技术选型对比与决策

### 推荐方案：Next.js + NestJS 全栈 TypeScript

#### 优势分析
- **开发效率**: 
  - TypeScript 全栈一致性，减少类型转换错误
  - 代码复用率高（前后端共享类型定义）
  - 团队学习成本低（统一技术栈）
- **项目适配性**: 
  - 中等规模团队（3-5人）高效协作
  - 快速迭代需求（12周交付周期）
  - 知识密集型应用（适合 RAG 系统）
- **生态支持**: 
  - NestJS 企业级框架，模块化清晰
  - Prisma ORM 与 PostgreSQL 深度集成
  - 丰富的 AI/ML 库支持（LangChain.js）

### 备选方案：React + FastAPI (Python)

#### 适用场景
- **AI 重度场景**: Python ML 生态更丰富
- **算法研究**: 需要频繁调整模型参数
- **数据科学**: 复杂的数据分析与可视化需求

#### 权衡考虑
- ✅ AI 生态丰富（scikit-learn, pandas, numpy）
- ✅ 模型部署成熟（MLflow, Kubeflow）
- ❌ 前后端技术栈分离，维护成本高
- ❌ 类型安全性相对较弱
- ❌ 团队技能要求多样化

### 微服务架构（未来演进方向）

#### 演进时机
- 用户规模 > 10,000
- 团队规模 > 15人
- 业务复杂度显著增加

#### 服务拆分策略
- **用户服务**: 认证、权限、用户管理
- **知识服务**: 文档处理、向量索引、检索
- **AI 服务**: 模型推理、会话管理
- **集成服务**: 飞书 API、第三方集成
- **通知服务**: 消息推送、邮件发送

## 系统性能与可扩展性设计

### 性能指标目标

| 指标类型 | 目标值 | 监控方式 |
|---------|--------|----------|
| **问答响应时间** | 平均 < 2s，99% < 5s | APM 监控 + 用户体验埋点 |
| **系统可用性** | ≥ 99.5% | 健康检查 + 故障自动恢复 |
| **并发处理能力** | 1000+ 在线用户，峰值 QPS > 500 | 负载测试 + 弹性扩容 |
| **数据一致性** | 权限违规 = 0，数据泄露 = 0 | 审计日志 + 安全扫描 |

### 缓存策略

#### 多层缓存架构
- **浏览器缓存**: 静态资源（CSS/JS/图片）
- **CDN 缓存**: 全球分发加速
- **应用缓存**: Redis 缓存热点数据
  - 用户权限信息（TTL: 30min）
  - 频繁查询的知识片段（TTL: 1h）
  - 会话上下文（TTL: 24h）
- **数据库缓存**: PostgreSQL 查询结果缓存

#### 缓存更新策略
- **写入策略**: Write-Through（确保一致性）
- **失效策略**: 基于版本号的智能失效
- **预热策略**: 系统启动时预加载热点数据

### 可扩展性设计

#### 横向扩展能力
- **无状态设计**: 应用服务无状态，支持水平扩展
- **数据库分片**: 按部门/时间维度分片（未来需求）
- **向量数据库**: 支持分布式部署与动态扩容
- **负载均衡**: Nginx + 健康检查 + 故障转移

#### 存储扩展策略
- **冷热数据分离**: 
  - 热数据（近3个月）：高性能 SSD
  - 温数据（3-12个月）：标准存储
  - 冷数据（>12个月）：归档存储
- **数据生命周期**: 自动化数据迁移与清理

### 监控与运维

#### 监控体系
- **基础设施监控**: CPU/内存/磁盘/网络
- **应用性能监控**: 响应时间、错误率、吞吐量
- **业务指标监控**: 用户活跃度、功能使用率
- **AI 效果监控**: 问答准确率、用户满意度

#### 告警机制
- **分级告警**: P0（立即处理）到 P3（日常优化）
- **智能降噪**: 基于历史模式的异常检测
- **自动恢复**: 常见故障的自动化修复

## 数据安全与合规实施

### 数据分类与保护策略

#### 数据分类等级
- **公开级别**: 官方介绍、公开课程信息
- **内部级别**: 会议纪要、项目进展、教学案例
- **机密级别**: 个人隐私、财务信息、核心算法
- **绝密级别**: 用户密码、API 密钥、加密证书

#### 分级保护措施
- **访问控制**: 基于数据等级的权限矩阵
- **存储加密**: AES-256 加密，密钥轮换策略
- **传输安全**: TLS 1.3 + 证书双向验证
- **审计追踪**: 详细的数据访问日志记录

### 隐私保护合规

#### 个人信息保护
- **最小化原则**: 仅收集必要的个人信息
- **脱敏处理**: 自动识别并脱敏 PII 数据
- **用户授权**: 明确的数据使用授权和撤回机制
- **数据删除**: 用户数据删除的完整性保证

#### 法规遵循
- **数据本地化**: 敏感数据境内存储
- **合规检查**: 定期的数据合规性审计
- **事件响应**: 数据安全事件应急预案
- **文档完善**: 隐私政策、用户协议等法律文档

## 风险评估与应对策略

### 技术风险

#### 高风险项
- **AI 模型性能不稳定**
  - 风险描述: GPT-4/Claude API 响应时间波动，影响用户体验
  - 应对策略: 多模型冗余 + 本地缓存 + 降级方案
  - 监控指标: 响应时间 P99 < 5s，成功率 > 99%

- **向量检索准确率低**
  - 风险描述: RAG 系统检索不到相关内容，影响问答质量
  - 应对策略: 多策略检索 + 混合搜索 + 人工标注优化
  - 监控指标: Top-K 命中率 > 80%，用户满意度 > 4.0/5

#### 中风险项
- **飞书 API 限流**
  - 风险描述: 超出 API 调用限制，影响数据同步
  - 应对策略: 请求队列 + 指数退避 + 增量同步
  - 监控指标: API 调用成功率 > 95%

- **数据库性能瓶颈**
  - 风险描述: 随着数据量增长，查询性能下降
  - 应对策略: 索引优化 + 查询优化 + 读写分离
  - 监控指标: 数据库响应时间 < 100ms

### 业务风险

#### 用户接受度风险
- **风险描述**: 用户对 AI 助手不信任，使用率低
- **应对策略**: 
  - 透明度设计: 显示数据来源和置信度
  - 渐进式引导: 从简单问答开始建立信任
  - 人工干预: 关键场景保留人工审核
- **监控指标**: 月活跃用户留存率 > 70%

#### 数据质量风险
- **风险描述**: 输入数据质量差，影响 AI 输出效果
- **应对策略**: 
  - 数据清洗: 自动化数据质量检查
  - 人工审核: 关键数据人工校验
  - 反馈机制: 用户纠错与质量改进
- **监控指标**: 数据完整性 > 95%，准确性 > 90%

### 合规风险

#### 数据安全风险
- **风险描述**: 敏感数据泄露，违反数据保护法规
- **应对策略**: 
  - 加密存储: 端到端数据加密
  - 访问控制: 最小权限原则
  - 审计追踪: 完整的操作日志
- **监控指标**: 安全事件 = 0，合规检查通过率 = 100%

#### 隐私保护风险
- **风险描述**: 个人信息处理不当，用户投诉增加
- **应对策略**: 
  - 隐私设计: 默认隐私保护
  - 用户控制: 数据删除与导出权利
  - 透明披露: 明确的隐私政策
- **监控指标**: 隐私投诉 = 0，用户满意度 > 4.2/5

### 应急预案

#### 系统故障应急
- **故障检测**: 自动化监控 + 智能告警
- **故障隔离**: 服务降级 + 流量切换
- **快速恢复**: 自动重启 + 数据备份恢复
- **事后复盘**: 故障分析 + 预防改进

#### 数据安全事件应急
- **事件识别**: 实时安全监控 + 异常检测
- **响应流程**: 立即隔离 + 影响评估 + 用户通知
- **恢复措施**: 漏洞修复 + 系统加固 + 监控强化
- **法规报告**: 监管报告 + 公开披露（如需要）

| 指标类型 | 目标值 | 监控方式 |

| **数据一致性** | 权限违规 = 0，数据泄露 = 0 | 审计日志 + 安全扫描 |

### 缓存策略

#### 多层缓存架构
- **浏览器缓存**: 静态资源（CSS/JS/图片）
- **CDN 缓存**: 全球分发加速
- **应用缓存**: Redis 缓存热点数据
  - 用户权限信息（TTL: 30min）
  - 频繁查询的知识片段（TTL: 1h）
  - 会话上下文（TTL: 24h）
- **数据库缓存**: PostgreSQL 查询结果缓存

#### 缓存更新策略
- **写入策略**: Write-Through（确保一致性）
- **失效策略**: 基于版本号的智能失效
- **预热策略**: 系统启动时预加载热点数据

### 可扩展性设计

#### 横向扩展能力
- **无状态设计**: 应用服务无状态，支持水平扩展
- **数据库分片**: 按部门/时间维度分片（未来需求）
- **向量数据库**: 支持分布式部署与动态扩容
- **负载均衡**: Nginx + 健康检查 + 故障转移

#### 存储扩展策略
- **冷热数据分离**: 
  - 热数据（近3个月）：高性能 SSD
  - 温数据（3-12个月）：标准存储
  - 冷数据（>12个月）：归档存储
- **数据生命周期**: 自动化数据迁移与清理

### 监控与运维

#### 监控体系
- **基础设施监控**: CPU/内存/磁盘/网络
- **应用性能监控**: 响应时间、错误率、吞吐量
- **业务指标监控**: 用户活跃度、功能使用率
- **AI 效果监控**: 问答准确率、用户满意度

#### 告警机制
- **分级告警**: P0（立即处理）到 P3（日常优化）
- **智能降噪**: 基于历史模式的异常检测
- **自动恢复**: 常见故障的自动化修复
